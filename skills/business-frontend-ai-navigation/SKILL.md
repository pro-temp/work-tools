# 业务前端 AI 友好化

让 agent 从真实业务页面和现有能力开始，快速找到可适配实现，减少重复手写。适用于管理后台、业务 Web/H5 应用和多业务前端工作区；普通功能开发不自动触发本改造。

## 范围与依据

先从目标目录、package、入口和消费者确认项目性质。组件库、设计系统、SDK、CLI 或通用工具包不采用本范式；混合仓库仅处理已确认的业务应用范围，库只作为依赖证据读取。用户意图优先，遵循目标仓库的实际约定，不把某个项目的框架、目录、组件名或命令变成全局规则。

制定或更新方案时，打开下方与改动相关的 OpenAI 官方页面核对当前内容；已在本次会话核实的内容可复用。链接迁移时通过官方站内搜索定位新页；无法联网时说明未核实最新内容，继续基于本地事实完成已授权工作。不要把链接存在或历史核对日期当成“规范永不过时”的保证。

- [GPT-6 Astra 官方指导](https://developers.openai.com/api/docs/guides/latest-model)：若任务指定 GPT-6，确认当前页面对应 Astra，不能静默套用其他型号。
- [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)：技能触发边界、按需读取、避免过度食谱化。
- [Build skills](https://learn.chatgpt.com/docs/build-skills)：技能格式、发现和渐进式加载。
- [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)：指令发现与目录作用域。

上述是官方机制与指导；下面是业务前端项目的实践选择，不声称 OpenAI 要求固定文件结构。首次编写核对日期：2026-09-15。

## 落地方式

- 从用户目标与当前导航缺口选择代表性场景，如列表、编辑表单、主从联动、业务选择器、权限、导出、接口封装。只追踪相关页面和依赖，不要求全仓预读。
- 保留或补一个短入口，通常在 README / AGENTS 中链接按需导航。导航连接“业务需求 → 本模块同模式源码 → 实际组件/API/helper”，给出路径及适用点，不复制完整业务页。
- 本模块和同实现模式优先。区分新旧页面体系、不同技术栈、应用自有组件、公共库及项目扩展；沿 import/注册核对所有权。相似页面不代表可复制业务权限、字段值、响应适配或基础设施。
- 小项目可用简短索引和 `rg` 命令；模块或模式较多、检索反复发生时才补本地只读工具。工具返回当前路径、行号、命中依据，限制默认范围和输出量，提供普通关键词和无命中后的查找路径。明确文本检索的遗漏与误匹配，不将候选标为合格模板。
- 已有 skill 复用同一个检索入口，保留专项契约；不支持 skill 的 agent 通过文档和源码完成任务。没有匹配 skill 不成为阻塞条件，不为普通导航新增全任务触发 skill。
- 能直接消费现有组件/helper 时直接使用；业务模式相同则最小适配；不适配时说明缺口并按本地风格补齐。索引不作为抽取共享代码、跨应用搬运或改业务逻辑的理由。
- 同步实际受影响的文档、skill 引用和生成入口。业务仓库内的 AI 导航文档和指令只使用本地相对引用，不写外网地址或联网核验要求；官方指导链接及核验流程保留在本全局 skill。仓库内材料自包含，不依赖个人全局 skill 路径；用户要求另行沉淀通用 skill 时，只提炼方法。

## 完成标准

用代表性任务核实“有 skill”和“仅文档/命令”均能到达真实实现及其依赖。检查引用有效、同模块优先、实现模式区分、无命中提示和实际扫描边界。新增检索逻辑时按风险验证范围与排序；已有生成表由原工具更新，不手工维护副本。

验证导航不需要启动业务服务或全量构建。只有改动应用运行契约时才按项目要求扩展验证。保留用户现有修改，报告实际交付、命令和验证限制；没有实测不承诺 token 降幅或完全消除从零实现。
