# 周报与月报汇总

把工作记录整理成简洁、直白、面向汇报的中文技术总结。周报与月报是工作成果摘要，不是测试验收单或免责声明；本 Skill 的汇报口径优先于代码交付场景的“验证过程 + 未验证项”报告习惯。

## 数据来源与只读取材

- 用户已提供足够工作记录、日报或多周周报时，直接按下文规则整理，不强制查询台账，也不默认混入另一来源（包括未落账的当前会话内容）
- 用户明确要求从台账取材，或请求周期报告但未提供材料时，读取本地 Worklog；先阅读 [Worklog CLI 共享说明](../worklog-work-tracker/references/worklog-cli.md)，使用同一绝对路径和用户级数据目录。此入口默认只读，不创建、修改、完成或重开任务，不修改现有周报自动化
- 按用户北京时间确定周期，显式传入 `timezone: Asia/Shanghai`，日期为左闭右开 `[from,to)`。自然周按周一至下周一、自然月按月初至次月初；用户给定包含结束日的范围时，`to` 为结束日次日。范围不明确且会改变结果时先澄清
- 基于 `report` 的 JSON 重新整理，不直接输出 CLI 的 Markdown。成果取 `effective_outcomes`，保留项目和模块语义并合并去重；`completion_events` 不能重复计为成果，`work_notes` 只作进展或阻塞，不写成已完成
- 读取失败时报告实际失败，不能伪装成“本期无成果”，不回退 Todoist，不初始化另一份数据

## 真实性边界与反叠甲

- **不虚构**：所有成果必须有记录支撑，不夸大影响或范围，不把未提交、未上线、未联调的工作写成“已上线/已全链路验收”，不执行证据命令或抓取链接
- **不叠甲**：对 `validation: passed` 的有效成果，直接写清楚做了什么及达成什么结果即可。不要抄写 `validation_note` 里的构建、编译、单测、回归项数或核对步骤，也不要在句尾补加“未联调真实环境”“现场设备未验证”“XX 场景未覆盖”“尚未提交或部署”等免责后缀
- **仅对未验证/失败项极简标注**：只有任务本身为 `validation: not_run` 或 `failed` 时，才在对应条目末尾用最短括注如实标出（如 `（待验证）`、`（验证未通过）`），不展开大段限制说明
- **历史导入说明按需触发**：`history_complete: false` 与 `history_notice` 仅在本期实际包含导入条目（`imported: true`）或查询区间早于/覆盖 `source_imports` 导入时间时，才需要说明数据范围边界（允许在末尾加一条最短编号“数据范围”说明，不充作成果或凑条数）；若本期完全晚于导入时间且全部为原生记录，无需附加“历史不完整”说明。标题和项目为当前快照值，不宣称历史还原

## 输出格式

使用纯文本“标题 + 编号列表”格式：

```text
本周周报

1. ...
2. ...
```

或：

```text
本月月报

1. ...
2. ...
```

- 默认输出中文；标题只写 `本周周报` 或 `本月月报`，用户未要求时不附日期范围、时刻或时区
- 正文使用自然纯文本，不对项目名、模块名或技术词加 Markdown 反引号，也不加 `（本对话补充）` 等来源括注
- 每条末尾不加句号，不添加前言、结语、表格或额外说明，除非用户明确要求

## 整理与精简原则

1. 识别每项工作的项目、功能模块、具体动作和结果，优先按功能模块或业务主题组织，不照搬原始记录顺序
2. 合并同一项目或同一功能链路中的相关事项，删除重复内容
3. 用“完成/迁移/改造/修复/升级 + 对象 + 核心结果”的方式表达，体现做了什么或解决了什么
4. 保留有辨识度的项目名、系统名、模块名和关键版本（如 WCS、wcs-front、GAIA、Wujie、Titan Host、thea-mobile、WMS、PDA、warehouse、版本号）
5. **默认省略实现细节与代码噪音**，除非用户明确要求展开：
   - 不出现分支名（如 `develop`、`feature/xxx`）和提交号
   - 不出现目录路径、文件名和接口/路由路径（如 `vue/stage`、`menu.json`、`/wms/...`）
   - 不出现类/函数/字段名、依赖包名、本地联调工具（如 `yalc`）及细碎计数（如“25 个页面”“11 项回归”“128 张表”）
6. 压缩过程描述和重复修饰，但不要把内容概括成“持续优化”“完善相关功能”等空泛表述

正反示例：

- 反例：`将海康 AGV 的容器类型和任务模板迁入 vue/hikagv，接入 Titan/Wujie 与 GAIA 注册表；前端迁移已推送 wcs-front develop，通过构建和模拟接口回归，未联调真实环境`
- 正例：`迁移 WCS 海康 AGV 模块至 wcs-front 多包工作区并接入新基座`

## 条数与抽象层级

### 周报

- 将零散工作按功能模块归类，通常整理为 6 至 8 条；信息较少时不为凑数拆分，信息较多时优先合并同类项
- 每条控制在 1 句话左右，保留能说明工作范围和结果的核心信息

### 月报

- 从多周周报中再次归并，跨周合并重复出现或持续推进的同一主题，控制在 8 条以内，不机械拼接各周内容
- 提高抽象层级，突出本月完成的主要功能、项目推进和关键问题解决

## 表达风格

- 简洁、直接、偏人话的技术工作总结
- 每条尽量只表达一个清晰主题，可在主题内合并紧密相关的成果
- 避免流水账、同义重复、夸张措辞和无法验证的价值判断
- 避免连续使用含义相近的“优化、完善、调整”，尽量明确具体能力或问题

## 输出前检查

- 标题是否仅为 `本周周报` 或 `本月月报`，正文是否无前言、结语和多余说明
- 是否使用连续编号列表、条目末尾无句号、正文未滥用反引号
- 是否合并同类项并去重，周报通常为 6 至 8 条、月报不超过 8 条
- 是否已剔除分支名、目录/文件路径、接口路径、代码符号和细碎计数
- 是否已去除验证流水账和免责式“叠甲”后缀（仅 `not_run`/`failed` 保留最短括注）
- 每条是否保留关键项目/模块名并清晰体现具体动作或解决的问题
